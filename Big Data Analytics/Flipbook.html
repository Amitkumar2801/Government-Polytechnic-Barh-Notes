Unit 1.1: The 5 Vs of Big DataPage: 02
Q. Explain the 5 Vs of Big Data with Real-Life Examples. (6 Marks ★ Imp)
★ Definition: The 5 Vs of Big Data — Volume, Velocity, Variety, Veracity, and Value — are the five core characteristics that define Big Data.
Detailed Explanation of Each V:
  1. Volume (Size): Massive amount of data in Terabytes/Petabytes. Ex: YouTube stores petabytes of daily videos.
  2. Velocity (Speed): High speed at which live data arrives & is processed. Ex: UPI fraud check in <1 sec; Google Maps live traffic.
  3. Variety (Formats): Mixed data types — Structured (SQL tables), Semi-Structured (JSON/XML), Unstructured (images, audio, CCTV).
  4. Veracity (Trust & Quality): Accuracy & cleanliness of data. Ex: Removing fake bot reviews or faulty sensor noise.
  5. Value (Usefulness): Real profit or smart insights gained after analysis. Ex: Netflix recommending movies users love.
2D Star Diagram (The 5 Vs):
✅ Advantages: Guides engineers to select the right storage (HDFS/NoSQL) & engine (Spark/Kafka).
❌ Disadvantages: Handling high Velocity + high Veracity simultaneously increases cost & complexity.
Conclusion: Without Veracity and Value, huge Volume, Velocity, and Variety are just useless digital noise.

Unit 2.3: Replication & Rack AwarenessPage: 11
Q. Explain Storing, Replication & Rack Awareness in HDFS. (4/6 Marks)
★ Definition: HDFS Replication automatically creates multiple copies (Default Replication Factor = 3) of every block across nodes and racks so data is never lost.
Step-by-Step Storing Process (Real Numerical Example):
  1. File Splitting: Suppose Amit uploads a 300 MB dataset. With 128 MB block size, HDFS splits it into 3 blocks: B1 (128 MB), B2 (128 MB), and B3 (44 MB).
  2. NameNode Lookup: Client asks NameNode where to write; NameNode picks 3 DataNodes.
  3. Write Pipeline: Client writes B1 to DN1 → DN1 copies to DN2 → DN2 copies to DN3.
  4. Rack Awareness Policy:
    • Copy 1: Local node on Rack 1.
    • Copy 2: Different rack (Rack 2) → protects against entire rack power failure!
    • Copy 3: Another node on Rack 2 → saves cross-rack network bandwidth.
2D Replication & Rack Awareness Diagram:
✅ Advantages: Survives full rack failure & enables fast parallel reads from nearest copy.
❌ Disadvantages: 3x replication consumes 3x raw disk space (300 MB file uses 900 MB).
Conclusion: Rack-aware pipelined replication guarantees both high availability and low network congestion.
Unit 2.3: Fault Tolerance & RecoveryPage: 12
Q. Explain Fault Tolerance and Data Recovery Mechanisms in HDFS. (6 Marks)
★ Definition: Fault Tolerance is HDFS's self-healing ability to keep running without data loss even when hard disks, DataNodes, or racks fail.
5 Core Fault Tolerance & Recovery Steps:
  1. Heartbeat (Every 3 sec): Each DataNode sends a live Heartbeat signal every 3s to NameNode.
  2. Dead Node Detection (10 min): Missing heartbeats for 10 min → NameNode marks DataNode DEAD.
  3. Automatic Re-Replication: NameNode detects blocks with <3 copies and orders healthy nodes to copy them to another healthy DataNode.
  4. Checksum Verification: Detects silent disk corruption during reads and fetches a clean copy automatically.
  5. Secondary NameNode & Safe Mode: Merges FsImage + EditLogs regularly; checks 99.9% blocks on startup.
2D Crash & Recovery Diagram:
✅ Advantages: Automatic zero-downtime self-healing; protects against disk corruption.
❌ Disadvantages: Re-replicating huge failed nodes temporarily consumes heavy cluster network bandwidth.
Conclusion: Heartbeats, checksums, and auto re-replication ensure 99.99% data durability in HDFS clusters.

Unit 2.5: MapReduce PhasesPage: 14
Q. What is MapReduce? Explain All Phases with WordCount Example. (6 Marks ★ Imp)
★ Definition: MapReduce is a parallel programming model that processes huge datasets in two core steps: Map() (filter/split) and Reduce() (aggregate/count).
6 Phases of MapReduce:
  1. Input Splits: Divides large file into 128 MB logical chunks.
  2. RecordReader: Converts splits into <Key, Value> pairs (e.g., line text).
  3. Map Phase: Mapper outputs intermediate <Word, 1> pairs.
  4. Shuffle & Sort: Groups values by identical key & sorts keys alphabetically.
  5. Reduce Phase: Sums grouped values to produce final totals.
  6. OutputFormat: Saves final <Key, Value> output permanently into HDFS.
2D WordCount Workflow Diagram:
✅ Advantages: Simple parallel code, auto fault recovery, scales to petabytes.
❌ Disadvantages: Writes intermediate results to disk → slower than Spark for iterative ML.
Conclusion: MapReduce simplifies distributed computing by automating splitting, shuffling, and failure recovery.

Unit 3 (Theory): Functional DependencyPage: 23
Q. Define Functional Dependency, Trivial/Non-Trivial FD & Closure (F⁺, X⁺). (6 Marks ★ Imp)
★ Definition: A Functional Dependency (X → Y) means attribute X (Determinant) uniquely decides Y (Dependent) in a relation R. Ex: Roll_No → Name.
FD TypeRuleExample
1. Trivial FDY ⊆ X (Y is subset of X){Roll_No, Name} → Name
2. Non-Trivial FDY ⊈ X (Y not inside X)Roll_No → Course
3. Completely Non-TrivialX ∩ Y = ∅ (No common attr)Emp_ID → Salary
Closure of FD Set (F⁺) & Attribute Closure (X⁺):
  • F⁺ (FD Closure): All FDs derivable from F using Armstrong's Axioms: 1) Reflexivity (Y⊆X ⇒ X→Y), 2) Augmentation (X→Y ⇒ XZ→YZ), 3) Transitivity (X→Y, Y→Z ⇒ X→Z).
  • X⁺ (Attribute Closure): All attributes decided by X (finds Candidate Keys).
  • Solved Ex: Given R(A,B,C,D), F={A→B, B→C, C→D}. Find A⁺: {A} → {A,B} → {A,B,C} → {A,B,C,D}=R ⇒ A is Candidate Key!
✅ Advantages: Eliminates duplicate data & update anomalies during DB normalization.
❌ Disadvantages: Over-normalization splits tables excessively, requiring slower SQL JOINs.
Conclusion: Functional Dependency & Closure mathematically guarantee clean, redundancy-free relational database design.

// 1. Unit 4.4: Data Modeling Best PracticesPage: 29
Q. Explain Best Practices for Data Modeling in MongoDB. (6 Marks)
★ Definition: MongoDB Best Practices are schema rules that optimize query speed, prevent hitting the 16 MB doc limit, and reduce RAM/disk waste.
  1. Design Around Query Patterns: Model collections based on how your app reads & writes most often.
  2. Embed 1-to-1 / 1-to-Few Data: Keep tightly linked data (User + Address) in 1 doc for 1-query speed.
  3. Reference 1-to-Many (Huge) Data: Store high-volume IoT logs separately with machine_id.
  4. Avoid Unbounded Arrays: Never let arrays grow endlessly inside a document.
  5. Use Proper Data Types: Store dates as ISODate & numbers as Int32/Double.
  6. Time-Series Bucket Pattern: Group hourly sensor readings into 1 doc per hour.
2D Decision Diagram:
✅ Advantages: Prevents 16 MB crashes, cuts query latency, minimizes disk I/O.
❌ Disadvantages: Embedded (denormalized) copies may need multiple updates if shared data changes.
Conclusion: Following query-driven modeling keeps MongoDB fast and scalable even at millions of documents.

Q. Explain MongoDB Indexing Types & Performance Optimization. (6 Marks)
★ Definition: MongoDB Indexing uses B-Tree structures to convert slow full scans (COLLSCAN) into fast index scans (IXSCAN). Every collection auto-indexes _id.
Index TypePurpose & Example Syntax
1. Single-FieldIndex 1 field: db.logs.createIndex({ machine_id: 1 })
2. CompoundIndex 2+ fields: db.logs.createIndex({ machine_id: 1, time: -1 })
3. MultikeyAuto-indexes elements inside an Array field (e.g., skills).
4. Text IndexKeyword search inside text fields: { notes: "text" }.
5. TTL IndexAuto-deletes old temporary logs after N seconds!
2D B-Tree Optimization Diagram:
✅ Advantages: Speeds up reads, sorting, & range queries on millions of engineering logs.
❌ Disadvantages: Uses extra RAM & slightly slows down INSERT/UPDATE write operations.
Conclusion: Selective Single-Field, Compound, and TTL indexes deliver peak MongoDB query performance.
